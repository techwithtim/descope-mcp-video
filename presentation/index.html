MCP servers / explained, then built

What the f*** is an
MCP server?

A program that gives an AI model a list of functions it's allowed to call. That's pretty much it.

By the end: one you built, on the internet, with a real login screen Claude and Cursor can sign into.
01 / the model on its own

A language model can't do anything

model
text in → [ model ] → text out # can't read your files # can't check your calendar # can't query your database # can't send a Slack message
So you give it tools. A tool is just a function with a name, a description and some parameters.
The model never runs it. It replies "call this one, with these arguments." Your code runs it and sends the result back.

05 / two ways to run one

Local vs remote

local · stdio

The client launches your server as a subprocess and pipes JSON through stdin / stdout.

python my_server.py

Only on your machine. Nobody else can touch it. What 90% of tutorials show.

remote · HTTP

Your server runs somewhere on the internet. It has a URL. Clients connect over HTTP.

https://notes.example.com/mcp

How every real product does it. GitHub, Notion, Stripe. Works from your laptop, phone, work machine.

The moment your server is a URL, you have a problem the local version never had.

08 / what's inside the token

Scopes say what. sub says who.

access token (decoded)
{ "sub": "U2abc...", ← the user "aud": "https://notes.example.com/mcp", ← YOUR server only "scope": "notes:read notes:write", ← what they approved "azp": "cursor-7f3a", ← which client (agent) "exp": 1757450000 ← short-lived }
Per-tool permissions. list_my_notes needs notes:read, delete_a_note needs notes:write. Only approved read? Write fails cleanly and the client can ask for more.
Per-user data. Every call has a user id, so notes are stored per user with one line of code.
Revoke one thing. One user, one agent, without touching anyone else. That's the difference between a demo and a product.
09 / one more piece

Clients register themselves

Dynamic client registration. Claude, Cursor and VS Code tell the authorization server "hi, I'm a client, here's where to send the user back" and get an id automatically.
You never set up Claude as an app by hand. Paste a URL into the client, the rest just happens.
what Cursor does when you paste the URL
POST /mcp → 401 GET /.well-known/oauth-protected-resource GET /.well-known/oauth-authorization-server POST /register → client_id # browser opens: login → consent POST /token → access_token POST /mcp Authorization: Bearer → 200
